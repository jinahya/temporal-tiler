== ChronoUnit Hierarchy

A tree of `java.time.temporal.ChronoUnit` values, ordered from coarsest to finest grain.

----
FOREVER
ERA
MILLENNIA
└── CENTURIES
    └── DECADES
        └── YEARS
            ├── MONTHS
            │   └── DAYS
            │       ├── HALF_DAYS
            │       │   └── HOURS
            │       │       └── MINUTES
            │       │           └── SECONDS
            │       │               └── MILLIS
            │       │                   └── MICROS
            │       │                       └── NANOS
            │       └── (WEEKS = 7 DAYS)
            └── WEEKS
----

NOTE: `WEEKS` does not divide evenly into `MONTHS` or `YEARS`. It branches off from `DAYS` as a fixed 7-day unit.

NOTE: `FOREVER` and `ERAS` are not supported by `TemporalTiler`.

== Supported Temporal Type / Grain Combinations

Not every `Temporal` type supports every `ChronoUnit` grain.
The temporal type must have enough precision for the requested grain -- e.g., `YearMonth` cannot be tiled by `DAYS` because it has no day component.

The table below shows which combinations are supported ({tick}) and which will throw `UnsupportedTemporalTypeException` ({cross}).

=== Rules of Thumb

* *Time-based grains* (`NANOS` through `HALF_DAYS`) require the temporal to support `NANO_OF_DAY`.
  `LocalDate`, `YearMonth`, and `Year` do not, so they cannot be tiled by time-based grains.
* *`DAYS` and `WEEKS`* require the temporal to support `DAY_OF_WEEK` / `DAY_OF_MONTH`.
  `YearMonth` and `Year` do not.
* *`MONTHS`* requires `MONTH_OF_YEAR` (or finer).
  `Year` does not support it.
* *`YEARS` and coarser* require `YEAR`, which all date-capable types support.
* For hierarchical tiling across precision boundaries, convert to a finer type first:
  `Year` -> `YearMonth.of(year, 1)` -> `LocalDate.of(year, 1, 1)`.
